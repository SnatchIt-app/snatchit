# CI additions (F18)

`.github/workflows/ci.yml`:
- `web` job now runs `npm run typecheck`, `npm run lint`, `npm run test` before `npm run build`; the `quality` job runs the package parity suites (`npx vitest run -c packages/vitest.config.ts`, which resolve `vitest` from the root install)
  (previously only the build ran; 165 web tests and 108 parity tests were ungated).
- new `deno-check` job: `deno check supabase/functions/*/index.ts` under Deno 2 (pinned `denoland/setup-deno@v2.0.3` by
  SHA). This is the first CI gate that type-checks the edge handlers with Deno's resolver; the root `tsconfig.json`
  excludes `supabase/functions`.

Behavioral edge-handler tests (`tests/*.test.ts` using `tests/helpers/edge-vm.ts`) run in the existing `quality` job
via `npm run test`. pgTAP suites run in the existing `db` job on the CLI-pinned fresh replay.

Expected first-run outcome of `deno-check` on this branch is recorded in the program report; a red result here is a
finding, not a reason to weaken the check.

## First Deno run (2026-09-06, run 34043668711 on `main`'s edges)

`deno check supabase/functions/*/index.ts` reports **21 pre-existing errors** (per-file inventory in
`deno_check_baseline_errors.txt`): supabase-js `SupabaseClient` generic mismatches at helper call sites
(`ReturnType<typeof createClient>` vs the created client type), a typed-select `SelectQueryError` on
`profiles.stripe_customer_id`, an unknown `transfer_id` property in a notification payload literal, and a union
argument in `sendPush` calls. They are type-level, not runtime, findings. The job is `continue-on-error: true` until
the packages are integrated (fixing them earlier would collide with files owned by Packages 2/3); the intent is to make
it blocking in the integration PR after a type-fix pass. Web/parity/root gates are blocking now.
