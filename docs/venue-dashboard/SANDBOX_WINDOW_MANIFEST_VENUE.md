## 6. Sequence and commands

```bash
export REF=ofaidukbieeekqaboscm VENUE_ACCEPT_WINDOW=<window id>
K="node venue/scripts/acceptance/accept.mjs --target sandbox --project-ref $REF"
$K --phase preflight                                   # V0  read-only baseline (counts, collateral, config digest, ledger, JWKS)
#     A: witness ledger count + Gate-2 census (before)
$K --phase apply --window $VENUE_ACCEPT_WINDOW         # V1  MUTATION migration + 24-statement ledger row
$K --phase verify-apply                                # V2  read-only
#     A: witness ledger count (+1) + Gate-2 census unchanged (after)
#     OWNER: S1 (§8)
$K --phase verify-exposure                             # V3  read-only: venue_api 404, catalog/venue 406, no schema dropped, hook unchanged
# build + serve the app under test at 2665a20 (runbook "Build and serve"), then:
$K --phase fixtures   --window $VENUE_ACCEPT_WINDOW    # V4  MUTATION §4
$K --phase api        --window $VENUE_ACCEPT_WINDOW    # V5  sign-ins + refused write attempts (C1–C7, H4, H5)
$K --phase browser    --window $VENUE_ACCEPT_WINDOW    # V6  H1–H7, C4, C6, C7, P1; writes 3 evidence PNGs
$K --phase precedence --window $VENUE_ACCEPT_WINDOW    # V7  MUTATION +2 scanner grants
$K --phase revocation --window $VENUE_ACCEPT_WINDOW    # V8  MUTATION −1 manager grant
$K --phase cleanup    --window $VENUE_ACCEPT_WINDOW    # V9  MUTATION exact-id deletes + 4 users
$K --phase postflight                                  # V10 read-only: back to baseline, scope unchanged
```

Any FAIL in V2, V3, V5 or V6 → stop: owner removes `venue_api` from exposed schemas (fast lever; views stay),
then V9 + V10, and report the evidence file.
